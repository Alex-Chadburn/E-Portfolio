# Software-test-reflection
   
## How can I ensure that my code, program, or software is functional and secure?
To ensure that code is functional and secure, I would implement a combination of automated and manual testing, including JUnit tests. While these methods can help identify edge cases and validate specific criteria, I recognize the importance of addressing potential security oversights, such as unchecked buffers. Incorporating security testing practices, like penetration testing, would also be necessary for larger projects.
    
## How do I interpret user needs and incorporate them into a program?
Interpreting user needs is crucial, as software is ultimately designed for them. I would focus on validating use cases such as ensuring a phone number is a 10-digit string to meet user expectations. Understanding that users may not be aware of technical details, I would strive to create software that functions intuitively and create a seemless experience.
    
## How do I approach designing software?
In approaching software design, I utilize pseudocode, flowcharts, and the rubber-duck method to clarify my ideas. I prioritize flexibility in my designs, such as using header files to separate different functionalities, like a parser and a struct that contains data based on what is parsed. Flexibility also includes user-based inputs; for example, instead of hardcoding a file to read from, I prompt the user for the file using getline. This approach, demonstrated in a previous project, reflects my design philosophy.
